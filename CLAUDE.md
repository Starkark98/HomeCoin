# CLAUDE.md — HomeCoin

Guidance for Claude Code when working in this repository. Household finance app that runs locally on Windows: Python/Flask server on `127.0.0.1`, encrypted SQLCipher database, vanilla JS single-page UI. Current version: see `VERSION` in `homecoin/app.py` (2.4.1 at the time of writing).

## Hard rules

- **Never read, copy or print the real data.** The data folder (`%LOCALAPPDATA%\HomeCoin\data` from 1.2.0; `data/` in the program folder up to 1.1.0, renamed `data.migrated-*` after the move: database, `keystore.json`, `backups/`) belongs to the user. Never call `db.migrate_data_folder()` without explicit throwaway `src`/`dst` in tests. Test only with the demo (`demo-data/`) or a throwaway folder set through `HOMECOIN_DATA_DIR`, and delete it afterwards.
- **No personal or financial data anywhere outside the encrypted database**: not in code, comments, examples, demo data, commit messages, docs or screenshots. Examples stay generic (Sample Home, Anna/Marco, `VWCE.DE`).
- **Keep the temporary import code** (`X-HomeCoin-Token`, Settings → Security): the user explicitly wants it. It must never reach `/api/auth/*`, `/api/backup*` (download, settings, compare, put back, restore), `/api/restore` or `/api/export/*`.
- **Only two network calls**, both optional: the price update to Yahoo Finance (tickers only) and the update check/download from GitHub releases (`updater.py`: HTTPS to GitHub hosts only, nothing about the user sent). No CDN, no telemetry, no other online service. Neither runs in the demo.
- **Updates are signed.** Never weaken `updater.py`: Ed25519 signature on the manifest with the embedded `PUBLIC_KEY`, newer version only, size + SHA-256 of every file, ZIP paths validated, git working trees never updated. The private key lives outside the repository (maintainer only); changing `PUBLIC_KEY` cuts off every installed copy.
- Do not commit or push without the maintainer's confirmation.
- **Honest attribution, everywhere:** every idea, feature, concept and design choice is the maintainer's (Starkark98); the code is written with the support of Claude Code. The project is free; its purpose is to help people take care of their money and build good habits (not charity). Never invent other purposes.
- **The README is the user guide** (the in-app *Help* opens it): plain English, step by step, and the correct technical term next to each plain explanation (e.g. "the annual return that accounts for when you added money: XIRR, a money-weighted return"). Accessible but professional. **Every change to the software updates the guide in the same change**: the feature's section, the screenshots when the UI changes (`dev\shots\capture.ps1` on the demo, maintainer side), the contents list. The guide follows the app menu: basics → Everyday → Planning → Wealth → Tools → Your data. Each page has the same structure: **What it is for** → screenshot → **What you see** → **What you can do** → **Tips**; long technical parts go in `<details>` boxes; new terms go in the Glossary. One screenshot per page (`docs/images/NN-page.png`, numbered in menu order, made by the maintainer's capture script on the demo). It must always match the current software. The "Why it exists" text is the maintainer's own words: never rewrite it.

## Commands (Windows, PowerShell)

Python is not on PATH: always use the project environment.

```powershell
.\setup.ps1                                   # creates .venv, installs requirements.lock with --require-hashes (Python 3.12–3.14, not the Store one)
.\HomeCoin.cmd                                # real instance → http://127.0.0.1:8765 (options: --port N, --no-browser)
.\HomeCoin-Demo.cmd                           # demo on 8766, sample data recreated at every start in demo-data\
.venv\Scripts\python.exe demo.py --port 8799 --no-browser   # demo for browser tests
```

- After changing Python code, **restart the server** (stop the process listening on the port, start `HomeCoin.cmd --no-browser` again). Static files only need a page reload. A restart locks HomeCoin and revokes the import code.
- Set `PYTHONIOENCODING=utf-8` when launching from tools (emoji in console output).
- In the browser use `http://127.0.0.1:<port>`, not `localhost` (Host check). A demo login takes ~2 s (scrypt).
- There is **no automated test suite** in the repository. Test with the Flask test client on a throwaway data folder:
  ```python
  os.environ["HOMECOIN_DATA_DIR"] = tmp   # BEFORE importing homecoin: db reads it at import time
  from homecoin.app import create_app
  app = create_app(8765); app.config["SERVER_NAME"] = "127.0.0.1:8765"
  # write requests need headers {"X-HomeCoin": "1", "X-Portfolio": "<space id>"} and a local Origin
  ```
  or in the browser against the demo, checking the console for errors.
- Installer: built outside the repository by the maintainer (Inno Setup, per user, Python 3.14 embeddable + `requirements.lock`), program in `%LOCALAPPDATA%\Programs\HomeCoin`, shortcuts run `python\pythonw.exe run.py`. The code must keep working both from the ZIP (`.venv`, console) and installed (embedded Python, no console). First start: `LOCK_VIEWS.setup → recovery(key, first) → welcome` in app.js.
- git is the one bundled with GitHub Desktop (`%LOCALAPPDATA%\GitHubDesktop\app-*\resources\app\git\cmd\git.exe`).

Key concepts:
- **Spaces** (`portfolios`, internal name; UI "space"): type `family` (Household) or `personal`. The client sends the active space in the `X-Portfolio` header (`?pf=` for export links); server helpers `pf()`, `PF_ACCOUNTS`, `own_account`, `visible_tx`. Transfers to accounts of other spaces are visible in both, are not income/expense, and count in net worth. `POST /api/categories/<id>/to-transfers` (2.3.0) turns the expenses of a category into transfers to another space's account (`dry_run` preview with per-row `items` (`convert`/`merge`/`duplicate`, `match_amount`, `unmatched`), `effect` on both spaces' reports and an `elsewhere` warning). With `merge`, "the same money" = amount within `tolerance` % (default 2, max 100, **of the smaller amount**: `similar_amount`) and date within `days` (default 5, max 31); a pairing beyond `CLOSE` = 2% (`far_apart`) is never applied by default: in the conversion it is only a `suggestion` until its expense id is in `confirm`, in /reconcile its row is `different` and unticked; paired by `util.best_pairs` (max pairs, then min cost; Hungarian per connected group — never greedy, which loses pairs with repeated similar amounts): first existing transfers from this space to the destination (the expense is a duplicate, deleted), then incomes of the destination (replaced; the transfer keeps the expense's amount); `unmatch` = expense ids the user unticked. Several destination accounts (`to_account_ids`, one other space; `to_account_id` still accepted): pairing looks in all of them, so each expense gets the account where its money arrived (`to_account_id` per item); `split` (default on): one expense = two incomes in two different accounts → two transfers (second part = expense − first, so together exactly the expense), the incomes deleted; unmatched → `default_account_id` (null = `keep`, stays an expense); `assign` {expense id: account | 0} per-row override (drops the pairing); `dest_balances` per account. Recurring items: `to_account_id` suggested by the matching recurring income (best_pairs on `same_flow`) or `"split"` (two recurring incomes in two accounts summing to it → two recurring transfers: the item + a copy); `recurring_accounts` overrides. **Recurring items are never changed automatically** (user rule): only the ids in `recurring_ids` (ticked by the user, none by default; plain items: no installments/principal/expected) become recurring transfers; `recurring_items` lists them with `planned` / `dest_income` warnings (`same_flow`: same frequency + similar amount + next due within `days`). Backup first. `POST /api/recurring/<id>/reconcile` (only from the sending space, only a plain recurring transfer to another space's account): pairs the past due dates (`best_pairs`) with the sending account's records (already linked, `lnk:` transfer to link — default on, `cnv:` expense to convert — default on for a flow-'other' category and for the item's own past payments still recorded as expenses, `own`, e.g. after changing a recurring expense into a transfer) and with the receiving account's incomes (`del:` deleted when the due date is covered, `inc:` orphan, default off: converting it moves it to the sending account); `rec:` recurring items for the same money (receiving income / sending expense / second transfer), default on, deleted (past transactions stay). `choices` {key: bool} override defaults; `effect` as above. `GET /api/recurring` also returns the recurring transfers coming from other spaces (`incoming`, `from_space`), read-only (PUT/DELETE/reconcile → 404 via `own_recurring`). Shared helpers `match_limits`, `same_money`, `same_flow`, `REC_COLS`. Tests `test_turn_into_transfers_never_counts_money_twice` and `test_turn_into_transfers_pairs_similar_repeated_money` check that the preview's effect equals the change in `/api/stats`.
- **Optional tabs** per space: `portfolios.features` (JSON). Core tabs are fixed; `OPTIONAL_FEATURES` = budget, obiettivi, emergenza, calendario, mutuo, ripartizione, investimenti, risparmio; hiding a tab never deletes data.
- **Amounts are integer cents** everywhere in the API and DB.
- **Reference currency** (1.1.0; 2.2.0 list): one per installation, `EUR USD GBP CHF CAD AUD NZD ZAR SGD HKD PHP INR AED MYR SEK NOK DKK ILS CZK MXN COP CLP BRL PLN JPY TWD KRW`, setting `currency` (global, no `@space`), `util.CURRENCIES` (namedtuple: symbol, locale, decimal, thousands, digits, prefix, space, name, short, steps, regions, date_excel, indexes, marks), **the only table**: app.js receives it through `/i18n.js` (no copy in JS); a new currency = one line there + its name translated, `util.currency_of`, `PUT /api/settings/currency` (needs `confirm: true`). It is a **label: amounts are never converted** (still integer cents, also for the currencies shown with 0 decimals: JPY, KRW, COP, CLP — the browsers' Intl decides, keep `digits` equal to it). Each currency uses its country's format (CHF `'` thousands as Chrome/Edge write it, BRL `R$ 1.234,56`, PLN `1 234,56 zł` with a no-break space and always grouped, JPY via `en-JP` for the plain ¥). A saved currency no longer offered (older test installs) is reported as `currency_unavailable` in `/api/meta` with a warning in Settings; `tools.LEGACY_RATE_INDEXES` keeps indexes of currencies no longer offered (empty since 2.2.0). Market prices are converted into it (`{base}{cur}=X`, London pence handled); `price_eur` keeps its historical name but holds the price in the reference currency, and a change clears it and `price_history`. UI: `setCurrency()` sets `CUR`, `CUR_SYM`, `LOCALE`, `DEC`, `DIGITS`, `SYM_FIRST` and the formatters; **never test a currency code for formatting** (use `DEC`, `DIGITS`, `money`, `money0`, `moneyK`, `moneyInput`, `moneyPlaceholder`, `num`, `CUR_SYM`). Server texts use `util.fmt_money`/`fmt_decimal` (half away from zero, like Intl). Loan indexes: `Currency.indexes` (`tools.RATE_INDEX_GROUPS` is derived; first = default), UI offers only the current currency's plus a loan's saved index; any index stays valid server side.
- **Number input**: one parser everywhere (`util.parse_number` server side, `normNum`/`parseMoney`/`parseSignedMoney`/`parseQty` in app.js). For money "1.500" = 1500 in euro (in dollars the dot is always the decimal separator); for quantities and prices "9.014" = 9.014. Display follows the reference currency.
- **Rebalancing** (1.1.0): `tools.rebalance` + `GET/POST /api/investments/rebalance` (POST calculates, `save: true` stores the settings in `rebalance@<space>`). Mode `class` (asset classes + `liquidità` = broker cash, `non specificato` = accounts valued as a whole) or `security` (`h:<holding id>`, `cash`, `acc:<account id>`); values are the same as the Allocation chart; buys only (new money to the gaps) or buys and sells (exactly to target); `excluded {class: [...], security: [...]}` leaves rows out (a security excluded in `security` also leaves its class); a threshold of 0 = not used. It never records trades.
- **Invested capital** (`tools.investments`, 2.4.0): the opening balance (`initial_balance`) of an investment account counts as money put in, dated `tools.opening_date()` (oldest of first transaction, valuation, trade, creation), in `invested`, the XIRR flows and the monthly series.
- **Monthly balance** (`tools.savings`): saved = month surplus (income − spent − other spaces), never the change in cash; "invested" = buys − sells of non-money-market securities, shown separately; money-market ETFs (`asset_class` `monetario`) count as cash.
- **Loans** (1.4.0): `recurring.amortization` NULL = French (constant installment), `'constant'` = constant principal (Italian / SAC). Use `tools.loan_plan(rec)` for a schedule and `tools.scheduled_amount(rec, n)` for the amount of installment n: constant-principal loans record each installment from the schedule and keep `recurring.amount` = the next installment (so every other `amount` reader stays right).
- **Languages** (2.0.0; 2.2.0: Deutsch, English, Español, Français, Italiano, Nederlands, Polski, Português (Brasil), 日本語, 繁體中文 (zh-TW), 한국어). **One language = one file** `static/i18n/<code>.json`: `"@meta"` (format in `i18n.LANGUAGE_FILE_FORMAT`: name, plural rule, suggested currency, months, month words, date/month patterns, default category/space/account names, bank-file encodings and headers, demo statement) + translations; `i18n.LANGUAGES` is read from the files, nothing in the code lists languages. **The English text is the key**: UI `T('…', {values})` and `tn(one, other, n)` in app.js (never `t`: local variables shadow it), server `i18n.t("…", **values)` / `i18n.tn()`; served with the language, its plural rule, months, date patterns and the currency table as `GET /i18n.js` (`window.HC_I18N`). **Never build a sentence from pieces**: no `${n} ${T('items')}` and no value between two `T()`; a number followed by a word is always `tn()`. Plural rules (CLDR): "one", "zero_one" (French), "pl" (Polish: the plural text is an object {few, many, other}, plus "one" when singular and plural share the English text), "none" (Japanese). The key must be a literal: `T(cond ? 'a' : 'b')` is not collected, write `cond ? T('a') : T('b')`. The language is stored in the keystore (`Vault.language()`, chosen in setup, `PUT /api/auth/language`); before setup cookie `hc_lang` or Accept-Language. Never build sentences from pieces; `translatePage()` handles index.html. Activity-log actions are stored in English and translated on screen; details are translated when written. Exports use the language for headers and sheets; the importer recognizes all six. Maintainer tools (outside the repo) check every key, placeholder, tag, plural form and `@meta` in every file, and find sentences built from pieces or English left in templates.
- **Category codes** (2.0.0, schema 16): default and system categories have `categories.code` (`util.SYSTEM_CODES`, `db.assign_category_codes`); always find them by code (`app.system_code()`, `TECH_CODES_SQL`), never by name, since names follow the language at creation and the user may rename them. Legacy names stay accepted as a fallback.
- **Import dates** (1.4.0): `importer.detect_date_order()` reads day/month vs month/day from the file; ambiguous files fall back to `util.DATE_ORDER_DEFAULT` by currency (USD = month first). `parse_date(value, order)`.
- **Investment plans**: a recurring transfer with `holding_id` buys units automatically at an estimated price (`external_id` `pac:<rid>:<date>`, note "estimated price"); editing the trade marks it "verified price"; unverified after 30 days → reminder.
- **Security guard**: Host check (DNS rebinding), `Sec-Fetch-Site: cross-site` rejected, writes need `X-HomeCoin: 1` + local Origin (CSRF), strict CSP, Permissions-Policy, no server signature, session cookie `hc_session_{port}` (`hc_session_demo_{port}` in demo), all `/api/*` except `/api/auth/*` return 401 while locked.
- **Database**: encrypted at rest, temp store in memory, `secure_delete`; restore runs `migrate()`.
- **Automatic backups** (2.3.0, user-controlled): settings in `DATA_DIR/backup-settings.json` (no data: `on_start`, `every` none/daily/weekly, `keep` 3–200, `dir`, `triggers` per reason in `db.BACKUP_TRIGGERS`), read before unlock. `db.backup_now(reason, force=False)` skips a switched-off start/trigger unless forced (full restore `pre-restore`, `manual`, `scheduled`, `pre-restore-tx` from the put-back are forced); `db.backup_dir()` falls back to `BACKUP_DIR` when the chosen folder is unreachable; `db.list_backups()` / `find_backup(name)` (names only, never paths from the caller). Periodic: `before_request` hook at most every 10 min while unlocked. API (all under `/api/backup…`, closed to the import code, except the read-only list alias `/api/auto-backups`): `GET/PUT /api/backup-settings`, `POST /api/backup-now`, `POST /api/backup-folder/open`, `POST /api/backups/compare` (transactions, recurring, accounts, categories, rules: deleted/changed/added; a reused id is "deleted + added": `same_row` = same `created_at`, kind, accounts and one of description/amount/date), `POST /api/backups/put-back` (`put_back`/`revert` {table: ids}; parents first; rows whose required account/space/category is gone are skipped and counted), `POST /api/backups/restore-all` (via `restore_payload`). Per account: `POST /api/accounts/<id>/compare-backup`, `POST /api/accounts/<id>/doubles`. UI: Settings → Data `drawBackups()`, `backupCompareModal()`, account card ⋯ menu (`doublesModal`, `compareBackupModal`). `keystore.json` is read and written only through `security.read_keystore`/`write_keystore` (one lock + cache: on Windows `os.replace` fails while another thread has the file open).
- **Updates** (1.2.1): `GET /api/update` (`?check=1` now, `?auto=1` at most every 20 h if `update_auto`), `PUT /api/update/settings`, `POST /api/update/apply` (session only: `/api/update*` is closed to the import code; backup `*-update.db` first; then exit via `HC_EXIT`, restart via `HC_RESTART` in tests). Settings keys `update_auto`, `update_checked`, `update_info` (global). UI: `loadUpdate()`, chip `#update-chip`, dot `#nav-update-dot`, Settings → Updates tab.
- **UI layout** (1.2.1): sidebar groups Everyday / Planning / Wealth / Tools (`.nav-group`, hidden when empty); rare actions in the top-right **⋯** menu; Settings tabs `SETTINGS_TABS` (`#/impostazioni?tab=general|spaces|security|data|updates`). New settings go in the tab where a user would look for them; keep the top bar for daily actions only.
- **Space color** (1.3.1): `applySpaceColor()` sets `--space`/`--space-ink`/`--space-fill`; used only for small "where am I" accents (active menu item, `#quick-add`, selected `.seg` tab line, `.toast.space`). Semantic colors (warnings, income/expense, charts, confirm buttons) never follow the space.
- **Page rendering** (2.4.x): `route()` gives each page its own box inside `#view` and a sequence number (`routeSeq`): a slower page opened earlier writes into a detached box, so it can never overwrite the newer page or show its error there. Render functions keep writing into the `v` they receive.
- **Redraws keep the focus** (1.3.1): `snapFocus()`/`restoreFocus()` around `route()` and calculators that re-render their own inputs (rebalancing); give re-rendered inputs an id or `data-k` + class so they can be found again.
- **Calculator warnings** (1.2.2): tools return `warnings`/`notes` lists of `{level: 'warn'|'info', text}` for what can make a result misleading (missing or stale prices, data gaps, inputs that cannot be acted on); the UI shows them with `calcNotes()`. Hard errors stay 400s; a new calculator gets both.
- **Demo** (`homecoin/demo.py`): must keep showing every feature with made-up data; when a feature is added, add sample data for it. `GET /api/demo/statement.csv` (demo only) feeds Import → "Try it with a sample bank statement".

## Conventions

- **Language**: code comments and docs in **US English**; every user-visible text written in English (sentence case labels) and translated into every other language file in the same change (`dev\scripts\i18n_keys.py --missing <lang>` must stay empty). Exceptions on purpose:
  - internal codes stay Italian because they are stored in existing databases: route keys (`#/movimenti`), feature keys, account type codes (`corrente`, `investimenti`…), asset classes (`azioni`, `monetario`, `liquidità`, `non specificato`…), categorizer sources `'regola'`/`'storico'`;
  - legacy Italian category names with a role in calculations must keep working next to the English ones (`Rettifica saldo`, `Altri investimenti (esclusi)`, `Versamenti conto casa`, `Versament%`, `prezzo stimato`): never rename user data, accept both spellings.
- **Versioning**: one numbering, same locally and on GitHub (SemVer from 1.0.0). A release updates `VERSION` in `homecoin/app.py`, `CHANGELOG.md` (newest first), the README badge and footer, and `SECURITY.md` if the supported line changes. The schema has its own `SCHEMA_VERSION`; add migrations to `db.migrate()` idempotently.
- **Style**: plain Python with small helpers, no framework beyond Flask; vanilla JS, no build step, no npm (Node is not installed). Match the existing compact style and comment density.
- **Guards over trust**: validate inputs server side (plausible dates 1990..today+366, integer bounds, unique names case-insensitive), block destructive changes that would corrupt data (selling units not owned, deleting accounts/holdings with trades, type changes with impact) and warn in the UI where a block is too strong.
- **Suggestions from history** exist where they help (transaction description/account/amount/category, recurring item name, rule keywords, and since 2.3.0 the transaction notes: `GET /api/notes` proposes the notes used with the same payee key, else with its main word, filtered by what is typed); deliberately **not** on the Transactions search.
- **Logo**: edit `static/img/logo.svg`; the icons in `icon/` are regenerated from it with a maintainer script kept outside the repository.

## Decisions already taken (do not reopen without asking)

- Price source stays **Yahoo Finance**; Investing.com was rejected (no API, scraping forbidden by its terms). Codes not quoted as-is (Morningstar `0P…`, ISIN) are resolved to the full Yahoo symbol (e.g. `.F`).
- Mortgage: fixed / variable / mixed rate (index + spread); indexes per reference currency in `util.CURRENCIES` (`Currency.indexes`, first = default; app.js gets them through `/i18n.js`), current value typed by hand (no download); APR, ARM caps and ancillary costs are deliberately out of scope.
- Languages and currencies (2.0.0–2.2.0): only languages really useful for a PC program (people who manage money on a PC, little English, securities on Yahoo): eleven (Deutsch, English, Español, Français, Italiano, Nederlands, Polski, Português (Brasil), 日本語, 繁體中文, 한국어) and 27 currencies; the currency is suggested from the browser's country, else the language. With an English interface: INR (grouped in lakh by `util.LAKH`), SGD, HKD, PHP, ZAR, NZD, AED, MYR, ILS, CZK and, by the maintainer's choice, SEK, NOK, DKK. Left out: ARS (inflation), PEN (no sure sources on loan indexes), CNY and Simplified Chinese (Yahoo blocked), right-to-left languages; Turkish only on request. **Every change to languages or currencies updates the documents in the same change; `dev\scripts\docs_check.py` checks the lists.** The demo stays in euros in every language. Number format = the currency's country, no separate format setting.
- Variable recurring items record nothing on their own: they link the real transaction (keyword + plausible amount) and forecast from the median of the last 6.
- Calendar: "cash in accounts" (operating accounts only) is distinct from the emergency fund "available reserve" (accounts + uninvested broker cash + money-market ETFs).
- Estimated regular income/expenses only for significant amounts (≥ 50 € and ≥ 5% of the largest).
- CSV/Excel exports are unencrypted by choice, with a warning and formula-injection protection.
- Few, broad categories; rules only for frequent payees.

## Known gaps

- No automated tests in the repo: the maintainer keeps a regression + fuzz suite outside it (made-up data only); last full run on 2.4.1.
- Automatic updates only work once the GitHub repository is public (the API returns 404 for a private one without a token) and for releases published with their signed manifest.
- `util.STOPWORDS` contains Italian bank words only (adding English ones would change payee keys of existing data).
- Activity-log rows written before the translation stay in Italian; old investment-plan notes may read half Italian, half English. Category names are not renamed when the language changes.
- Windows only (launchers, data-folder ACL); the Python code is untested elsewhere.
